For MusicVizion, plan first, keep costs as close to zero as possible, and ask for authorization on things that cost money per use.

**Why:** The user explicitly requested this cost and approval policy.

**How to apply:** Prefer local processing and no-paid-call defaults. Get explicit authorization before billable API calls, tests, build services, or other per-use spending. Plan approval alone is not spending authorization.

Feature-only commentary must not be described as Grok hearing audio. Disclose the difference and obtain approval before considering a different provider.

**Why:** The user explicitly requires verified audio capabilities and truthful disclosure of computed-feature limitations.

**How to apply:** Confirm the selected model's actual input modalities before promising listening. Separate public list prices from a verified maximum charge, and obtain a separate exact live-test budget before any billable test.
